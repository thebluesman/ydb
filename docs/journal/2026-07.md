  onto YDB's existing ones, **fully reset YDB's ledger data** (Accounts, Transactions, Categories,

- **[scope]** The SMS→Signal→YNAB capture pipeline (previously "outside this repo, already decided
  separately") now has a home: a new sibling repo, `expense-capture`
  (`~/Documents/Projects/expense-capture`), scaffolded the same session with its own docs/ADRs. See
  that repo's `docs/adr/` for the Signal-over-Telegram and shared-group-routing decisions.
- **[scope]** Built Phase 1 "Import from YNAB" pipeline on branch `ynab-import-pipeline`: `lib/ynab.ts`
  (API client), `lib/ynabImport.ts` (shared preview/commit logic including transfer pairing), three new
  routes under `app/api/ynab/`, `YnabImportManager` Settings component, and `Transaction.ynabId` column
  for idempotency. Covers all transaction types (income, expense, and internal YNAB transfers). Typechecked,
  22 new unit tests all passing, not yet merged.
- **[decision]** Opening balance handling: YNAB's "Starting Balance" transactions (one per account) are
  imported as regular transactions, and every account recreated during the ledger reset (ADR-0003) must
  have `openingBalance: 0`, so YNAB's row is the sole source of each account's opening balance in YDB.
  Documented as a load-bearing requirement in `docs/adr/0003-full-reset-before-ynab-import.md` and
  `docs/research/ynab-vs-ydb/findings.md`.
- **[refactor]** Fixed a silent correctness bug: YNAB's real incremental-sync parameter is
  `last_knowledge_of_server`, not `server_knowledge` — the latter is silently ignored and returns full
  history, so every "incremental" sync would have rescanned all data with no error. Corrected in
  `lib/ynab.ts`.
- **[ops]** Logged YNAB API shape surprises to `docs/research/ynab-vs-ydb/findings.md`: split
  transactions expose legs as `subtransactions[]`, category names can be emoji-prefixed and include
  YNAB's control buckets (`Inflow: Ready to Assign`, `Split`), and `payee_name` is nullable (importer
  falls back to memo, then a placeholder).
- **[refactor]** Fixed import pipeline robustness: delta cursor no longer advances past skipped rows
  (preventing data loss when a row is unmapped, incomplete, or ADR-0004-blocked), same-account transfer
  pairs pre-filtered in `planYnabImport`, and `$transaction` timeout bumped to 60s for full-history
  first imports. Reuse of pre-computed `accountCurrencies` map avoids re-querying on commit. Tests
  expanded from 22 to 34; added full-Prisma idempotency integration test (`planYnabImport` → commit
  cycle on fresh DB). → `docs/ynab-import-fix-plan.md`.
- **[decision]** ADR-0004: YNAB mutations (edits/deletions since last import) are detected by content
  fingerprint against the stored row and reported for manual reconciliation, never auto-applied or
  auto-deleted. Implemented across `lib/ynab.ts` (tombstones returned), `lib/ynabImport.ts` (plan
  counters), `app/api/ynab/import/route.ts` (commit-path handling), and YnabImportManager UI
  (expandable report blocks). See `docs/adr/0004-ynab-mutations-detect-and-report.md`.
