- **[decision]** ADR-0033 (Accepted, 2026-10-21): the sign-branch detector steps back when the WHERE clause pins a specific, non-Uncategorized category. "What did I pay on my car loan" and "what did I spend on auto loans" produce identical SQL, so the shape is ADR-0019's mirror case and not decidable from the SQL; the prompt rule governs it. This narrows ADR-0016 (both stay Accepted). Accepted cost: a category-pinned spend query that omits the transfer guard is no longer caught. Fixes the `car-loan-payment-transfer-mirror-case` false-positive refusal (confirmed by running the guard against the fixture DB); the live eval case still fails, now because the model adds an account filter plus the transfer guard and gets no-data. → `docs/adr/0033-sign-branch-detector-steps-back-on-a-category-pin.md`, PR #71, commit `d7ddbd6`.

- **[scope]** PR #70 corrected the SQL prompt's split-leg rule, which was described backwards ("exclude parents") and covered only spend sums. The rule now applies to every aggregate, with a new category-filtered COUNT worked example; `groceries-transaction-count` went from 0/2 to 2/2 passing. → PR #70, commit `fba4d88`.
