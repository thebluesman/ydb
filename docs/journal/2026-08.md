- **[decision]** ADR-0020 (Accepted, 2026-08-01): Money units are normalized server-side, not inferred by the narrator. Narration's `chatKnowledge.ts` instruction to "infer from context" was *accurate*—two legitimate query shapes deliver raw integer cents to narration today: row-level `Transaction.amount` projections (including bare `SELECT *`, which ADR-0017 kept legal) and `Account.creditLimit`. The SQL prompt's `/100.0` rule covers only aggregates, leaving these shapes unspecified. The decision: a route-level classifier walks the final SELECT's projection list, resolves each against schema-known money columns, converts unconverted cents, and refuses as `out-of-scope` any unresolvable projection (CTEs, multi-table joins without explicit qualification, subqueries)—a fail-closed stance, opposite to ADR-0018, justified because failing open would manufacture confident wrong numbers. This becomes the pipeline's **second** post-execution guard (after ADR-0017's star-expansion check); flagged as signal to revisit phase ordering under ADR-0012's loop architecture. Ticket scoped to `@backend-engineer` with six required test cases including double-division and `COUNT(amount)` false-positive checks. → `docs/adr/0020-money-units-normalized-server-side.md`, commit `d1f7b94`.
